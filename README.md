# بوت 𝐀𝐘 COMMUNITY

بوت Discord باستخدام JavaScript و`discord.js`، ويضم أوامر الإدارة والتحذيرات ولوحة الدعم والتقديم والسحوبات والألعاب المطلوبة. تحفظ التحذيرات والتقديمات وإعدادات اللوحات والتذاكر والسحوبات ومشاركيها في قاعدة SQLite داخل `data/bot.sqlite`.

## الملفات

- `src/index.js`: تشغيل البوت والأوامر والتذاكر والتقديمات.
- `src/commands.js`: تعريف أوامر Slash وخياراتها وصلاحياتها.
- `src/database.js`: إنشاء قاعدة البيانات والاستعلامات الدائمة.
- `src/community-games.js`: منطق السحوبات والروليت وألعاب التخمين والزر الأخضر.
- `src/afk.js`: تفعيل الغياب وتسجيل المنشنات وإظهار ملخص العودة.
- `src/deploy-commands.js`: تسجيل الأوامر في السيرفر.
- `.env.example`: نموذج إعداد بيانات Discord؛ انسخه إلى `.env` ولا تشارك الملف.
- `package.json`: المكتبات وأوامر التشغيل.

## التجهيز في Discord

1. أنشئ تطبيقًا وبوتًا من [Discord Developer Portal](https://discord.com/developers/applications)، ثم انسخ توكن البوت ومعرف التطبيق.
2. من صفحة **Bot** فعّل **Server Members Intent** و**Presence Intent** و**Message Content Intent**. يحتاج البوت أيضًا إلى الوصول إلى السيرفر. تفعيل Message Content مطلوب كي يقرأ إجابات ألعاب تخمين البلد والشخصية.
3. أنشئ رابط دعوة OAuth2 بنطاقي `bot` و`applications.commands`، وامنح البوت الصلاحيات اللازمة: عرض القنوات، إرسال الرسائل، تضمين الروابط، إرفاق الملفات، إدارة الرتب، مهلة الأعضاء، وإدارة القنوات. يلزم أيضًا إذن **Mention Everyone** لإرسال أخبار `@everyone`.
4. أضف البوت إلى السيرفر. أعطِ رتبة البوت ترتيبًا أعلى من الرتب التي سيمنحها، وأعلى من الأعضاء الذين سيطبق عليهم المهلة.

## التشغيل في Visual Studio Code

1. ثبّت Node.js إصدار 22 أو أحدث، ثم افتح مجلد المشروع في VS Code.
2. افتح الطرفية من **Terminal > New Terminal** ونفّذ:

   ```powershell
   npm.cmd install
   ```

3. انسخ `.env.example` إلى ملف جديد اسمه `.env`، ثم أضف توكن البوت ومعرف التطبيق. لا ترفع `.env` أو تشارك محتواه. يمكن إضافة `GUILD_ID` اختياريًا لحذف أوامر السيرفر القديمة بعد نشر الأوامر العامة.
4. سجّل الأوامر العامة للتطبيق:

   ```powershell
   npm.cmd run deploy
   ```

5. شغّل البوت:

   ```powershell
   npm.cmd start
   ```

يجب أن يبقى أمر التشغيل يعمل كي يستجيب البوت. عند تعديل تعريفات الأوامر في `src/commands.js`، أعد تشغيل `npm.cmd run deploy`. الأوامر العامة متاحة في كل سيرفر تمت إضافة البوت إليه، وقد يتأخر ظهورها في Discord لبعض الوقت. تأكد من تضمين النطاق `applications.commands` في رابط دعوة البوت؛ إذا لم يظهر الأمر في سيرفر صديقك، أعد دعوة البوت بهذا النطاق. بعض أوامر الإدارة تظل محصورة بأصحاب الصلاحيات المناسبة.

## الأوامر

- `/مساعدة` يعرض جميع الأوامر مصنفة داخل Embed مع صيغ الاستخدام.
- `/مسح العدد` يحذف من 1 إلى 100 من أحدث رسائل الروم الحالي. يتطلب صلاحية إدارة الرسائل، ولا يحذف Discord الرسائل الأقدم من 14 يومًا عبر الحذف الجماعي.
- `/ارسال` يرسل رسالة عادية باسم البوت في الروم المحدد.
- `/رتبة` و`/تايم` و`/تكلم` لإدارة الرتب والمهلة. تقبل المدة مثل `30m` أو `2h` أو `3d`، حتى 28 يومًا.
- `/قفل-روم` و`/فتح-روم` لقفل الكتابة على `@everyone` في الروم الحالي أو روم تحدده. يحفظ البوت إعداد الكتابة السابق ويستعيده عند الفتح.
- `/طرد` لإزالة عضو من السيرفر، و`/بان` لحظره، و`/رفع-بان` لرفع الحظر باستخدام آيدي العضو.
- `/معلومات` يعرض معلومات السيرفر، أو معلومات العضو عند تحديده.
- `/لفل [العضو]` يعرض المستوى وXP والتقدم للمستوى التالي. تمنح الرسائل 15 إلى 25 XP بحد أقصى مرة كل دقيقة، ويمنح الصوت 10 XP كل دقيقة عند وجود عضوين بشريين على الأقل في قناة غير AFK؛ لا تُحتسب رسائل البوتات أو أعضاء الصوت المكتومين بالكامل.
- `/لفل-إعداد روم` للمسؤول لتحديد روم تهاني الارتقاء. يحفظ البوت المستويات في SQLite، ويرسل التهنئة عند تجاوز XP المطلوب للمستوى التالي.
- `/تصنيفات` يعرض لوحة ترتيب متفاعلة للخبرة الإجمالية المحسوبة من المستوى وXP المحفوظين، إضافة إلى تصنيفي الرسائل والصوت مع اختيار التصنيف وأزرار الصفحات. يبدأ احتساب XP الرسائل والصوت المنفصل من وقت تفعيل التتبع؛ لا يمكن فصل XP الرسائل عن الصوت في البيانات التاريخية القديمة.
- `/لفل-فويس روم` للمسؤول لتحديد روم مستقل لإعلانات الارتقاء الناتج عن XP الصوت. تحتاج إعداداته صلاحية عرض الروم وإرسال الرسائل للبوت؛ إن لم يُحدد روم صوتي، تستخدم تهاني الصوت روم `/لفل-إعداد`.
- `/إعداد_جوائز_المستويات المستوى الرتبة` للمسؤول لحفظ رتبة جائزة لكل مستوى؛ عند وصول العضو للمستوى المحدد تُضاف الرتبة تلقائيًا. استخدم `/عرض_جوائز_المستويات [الصفحة]` لعرض الجوائز و`/حذف_جائزة_مستوى المستوى` لحذف جائزة. تُحفظ الجوائز وسجل منحها في SQLite، ولا تُمنح الجائزة بأثر رجعي لمن وصل إلى المستوى قبل إعدادها. يحتاج البوت إلى صلاحية إدارة الرتب وأن تكون رتبته أعلى من الرتبة المراد منحها.
- `/تحذير` و`/عرض-تحذيرات` و`/إزالة-تحذيرات` لإدارة التحذيرات. حذف التحذيرات يتطلب تأكيدًا ثانيًا يوضح العضو وعدد التحذيرات.
- `/أخبار` يرسل الخبر مع `@everyone`، ولا يعمل ما لم تتوفر صلاحية المنشن للمسؤول والبوت في الروم.
- `/رد-تلقائي الكلمة الرد` يحفظ ردًا تلقائيًا للكلمة أو العبارة المحددة، ويحدّث الرد عند استخدام كلمة محفوظة من قبل. `/الردود-التلقائية` يعرض الردود المحفوظة، و`/مسح-رد-تلقائي` يعرض قائمة تفاعلية لاختيار الرد وحذفه، مع صفحات إضافية عند وجود أكثر من 25 ردًا. يرسل البوت الرد عند ظهور الكلمة ككلمة مستقلة في رسالة عضو، ولا يسمح الرد بمنشن الأعضاء تلقائيًا. الأوامر للمسؤولين وتُحفظ إعداداتها لكل سيرفر في SQLite.
- `/بينغ` يعرض زمن استجابة البوت.
- `/afk` يفعّل وضع الغياب، مع سبب اختياري. عند منشن العضو يُسجل صاحب المنشن ورابط رسالته، وعند أول رسالة للعضو بعد عودته يعرض البوت مدة غيابه وجميع الأشخاص الذين ذكروه وروابط الانتقال إلى رسائلهم. حالة الغياب والمنشنات محفوظة في SQLite.
- `/تذاكر-إعداد` ينشر لوحة الدعم بزر فتح واحد، ويضبط رتبة فريق الدعم. تظهر داخل التذكرة أزرار الإغلاق وإعادة الفتح والحذف؛ لا يمكن للعضو امتلاك أكثر من تذكرة مفتوحة.
- `/تقديم-إعداد` ينشر لوحة التقديم ويحدد روم استقبال الطلبات. النموذج يحتوي الأسئلة الخمسة المحددة، وقرارات القبول والرفض متاحة لمن لديه صلاحية إدارة السيرفر.
- `/سحب` ينشئ سحبًا في الروم المحدد. أدخل الجائزة والمدة مثل `30m` أو `2h` أو `3d` وعدد الفائزين من 1 إلى 20. الحد الأقصى للمدة 30 يومًا، ويُختار الفائزون عشوائيًا دون تكرار. تبقى بيانات السحب ومشاركوه محفوظين بعد إعادة التشغيل.
- `/روليت` للمسؤولين: حدد الروم، ثم ينضم المشاركون بزر **دخول الروليت** ويختار مسؤول الفائز بزر **إجراء السحب**. اختيار عشوائي بلا مراهنات أو أموال.
- `/زر-أخضر` يبدأ لوحة 5×5. لكل عضو محاولة واحدة، وأول من يضغط المربع الصحيح يفوز؛ تنتهي الجولة بعد دقيقتين إن لم يفز أحد.
- `/تخمين-البلد` و`/تخمين-الشخصية` لبدء جولة في الروم المحدد. يجيب الأعضاء برسالة في الدردشة، وأول إجابة صحيحة تفوز. تنتهي الجولة بعد دقيقتين وتُكشف الإجابة بعدها.
- `/خمن-الصورة` يرفق صورة فعلية داخل رسالة Discord لموضوع معروف، وأول إجابة صحيحة تفوز. تنتهي الجولة بعد دقيقتين وتُكشف الإجابة بعدها.
- `/ميم` يولّد صورة ميم عشوائية بقالب ونص عربي عبر `memegen.link`، ثم يرفقها داخل Embed. يتطلب اتصال إنترنت.

الأوامر الإدارية وأزرار قرارات التقديم متاحة للمسؤولين الذين لديهم الصلاحية المطلوبة لكل أمر: إدارة الرومات للقفل والفتح، وطرد الأعضاء للطرد، وحظر الأعضاء للحظر ورفعه. يلزم فريق الدعم رتبة الدعم المحددة للتعامل مع أزرار التذاكر.

## اختبار السحوبات والألعاب

1. فعّل **Message Content Intent** من صفحة البوت في Developer Portal، ثم أعد تشغيل العملية بعد النشر.
2. نفّذ `npm.cmd run deploy` لتحديث الأوامر العامة، وأعد تشغيل البوت باستخدام `npm.cmd start`.
3. جرّب `/سحب` بمدة قصيرة مثل `1m`، شارك بحسابين عبر الزر، وتحقق من إعلان الفائز. أعد تشغيل البوت قبل انتهاء سحب آخر للتأكد من استعادة مؤقته ومشاركاته.
4. جرّب `/روليت`، وانضم بزر المشاركة، ثم اجعل مسؤولًا يختار الفائز.
5. جرّب `/زر-أخضر` واضغط مربعًا خاطئًا ثم تحقق أن المحاولة الثانية مرفوضة، أو اختبر الفوز مباشرة في جولة جديدة.
6. جرّب لعبتي التخمين برسائل صحيحة وخاطئة، وتحقق من انتهاء الجولة وكشف الإجابة بعد دقيقتين عند عدم وجود فائز.


## النشر على Railway

1. ارفع المشروع إلى GitHub (أو استخدم Railway CLI).
2. من [Railway](https://railway.app) اضغط **New Project** → **Deploy from GitHub repo** واختر المستودع.
3. Railway يكتشف Node.js تلقائيًا. تأكد أن أمر التشغيل هو `npm start`.
4. من تبويب **Variables** أضف:
   - `DISCORD_TOKEN` = توكن البوت
   - `CLIENT_ID` = معرّف التطبيق
   - `GUILD_ID` = (اختياري) معرّف السيرفر
5. **مهم لحفظ البيانات**: اضغط **+ New** → **Volume** واربطه بالمسار `/data`. ثم أضف متغير:
   - `DATA_DIR` = `/data`
   بدون الـ Volume، قاعدة SQLite تُحذف مع كل إعادة نشر.
6. بعد أول نشر ناجح، افتح **Shell** داخل الخدمة وشغّل مرة واحدة:
   ```
   npm run deploy
   ```
   هذا يسجّل أوامر السلاش في Discord. أعد تشغيله فقط عند تعديل الأوامر.
7. فعّل الـ Intents في Discord Developer Portal (Server Members + Presence + Message Content).

### ملاحظات Railway
- البوت يحتاج Node 22+ (موجود في `package.json`).
- `better-sqlite3` يُبنى تلقائيًا عبر Nixpacks.
- إذا فشل البناء بسبب native modules، أعد النشر بعد التأكد من Node 22.
- البيانات (تحذيرات، مستويات، تذاكر، سحوبات...) تُحفظ في `/data/bot.sqlite` عند استخدام الـ Volume.

## النشر على Wispbyte

1. أنشئ خادم Node.js في Wispbyte واختر Node.js 22 أو أحدث.
2. ارفع ملفات المشروع إلى مجلد الخادم، مع تضمين `src` و`package.json` و`package-lock.json` و`.env.example`. لا ترفع `node_modules` أو ملف `.env`.
3. من إعدادات متغيرات البيئة في لوحة Wispbyte، أضف:
   - `DISCORD_TOKEN`: توكن البوت من Discord Developer Portal.
   - `CLIENT_ID`: معرّف تطبيق Discord.
   - `GUILD_ID`: اختياري؛ عند ضبطه يحذف أمر النشر نسخة أوامر السيرفر القديمة بعد تسجيل الأوامر العامة.
4. اجعل أمر تثبيت الحزم `npm install` وأمر بدء التشغيل `npm start`. يشغّل `npm start` الملف `src/index.js` ويُنشئ مجلد `data` وقاعدة `data/bot.sqlite` تلقائيًا.
5. سجّل أوامر Discord مرة واحدة من Console الخادم بتشغيل `npm run deploy`، ثم ابدأ الخادم. أعد تشغيل أمر النشر فقط عند تغيير تعريفات الأوامر في `src/commands.js`.
6. تأكد أن تخزين ملفات الخادم دائم بين مرات إعادة التشغيل؛ قاعدة `data/bot.sqlite` تحتوي بيانات البوت. خذ نسخة احتياطية منها قبل حذف الخادم أو إعادة تثبيته.

إذا ظهر خطأ متعلق بـ`better-sqlite3`، تحقق من أن نسخة Node.js على الخادم 22 أو أحدث ثم أعد تثبيت الحزم على الخادم باستخدام `npm install`، ولا تنقل مجلد `node_modules` من جهاز Windows.
